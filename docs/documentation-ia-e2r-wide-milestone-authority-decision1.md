# E2R-wide milestone planning authority decision 1

Date: 2026-09-24

Status: **HUMAN-SELECTED ROADMAP PLANNING-AUTHORITY DECISION**

## Decision

The Human selects the `Proposed E2R-wide milestones` map in
[`docs/roadmap.md`](roadmap.md#proposed-e2r-wide-milestones) as the single
canonical planning authority for the E2R ecosystem milestone sequence.
Milestone descriptions, order, priority, and completion status are unchanged
by this decision.

The Hub milestone list is not deleted as a responsibility. It becomes a
Hub-application-specific planning supplement under the existing
[`E2R ecosystem hub / portal track`](roadmap.md#e2r-ecosystem-hub-portal-track)
anchor. It may retain Hub-owned presentation, user-entry, and browser-workspace
concerns, but must not define a second sequence for ecosystem goals already
owned by the E2R-wide map. The E2R-wide sequence does not make Hub
implementation, acceptance, or completion implicit.

## Responsibility boundary

The E2R-wide map remains authoritative for ecosystem-level goals and their
existing sequence, including first-use ecosystem entry, canonical
cross-application samples, repeatable interoperability evidence, Validator
compatibility, History/chronology, app/pack manifests, Dictionary/Semantic and
external-vocabulary boundaries, and evidence-gated ecosystem releases.

The Hub supplement retains only the Hub's contribution to those goals and
Hub-specific responsibilities, including:

- Hub catalog/status-card presentation and onboarding paths;
- presentation of canonical samples and Hub-provided application/Handoff
  entry points, without claiming the broader interoperability gate complete;
- Hub-facing display of capability/compatibility and pack information, without
  redefining ecosystem manifests, compatibility policy, or pack foundations;
- access to the existing E2R Self-Description Dataset, which remains owned at
  its existing specification-repository path and is not duplicated or changed;
- browser-local preference and workspace investigation, including the
  existing same-origin constraint and the need to investigate an explicit
  bridge or server-backed workspace before assuming cross-origin sharing;
- Hub-specific portal release mechanics, subordinate to the E2R-wide
  ecosystem release responsibility.

These are scoped responsibilities, not new acceptance, implementation, or
priority decisions. Existing non-authorization boundaries remain: no Core
change, universal application UI, automatic interpretation of unknown
metadata, implicit Dataset content for preferences/workspace state, or
assumption of cross-origin storage sharing.

## Evidence and non-inference

The basis is the comparison in
[`Hub vs E2R-wide milestone authority — decision preparation 1`](documentation-ia-hub-vs-e2r-wide-milestone-authority-decision-preparation1.md),
the accepted Hub IA and Milestone 2 acceptance authorities, and current
read-only Hub implementation evidence recorded there. Current source includes
some Hub-generated Dataset Handoff links. That implementation evidence does
not establish Human acceptance or completion of the broader E2R-wide
interoperability milestone, nor does any Hub implementation automatically
complete an E2R-wide milestone.

## Anchor and history boundary

The Human-selected compatibility rule is to preserve Roadmap anchors that
have actual inbound references from the current canonical E2R workspace, not
to preserve every historical heading for hypothetical external deep links.
The implementation checkpoint rechecked those references: the Hub and
E2R-wide parent anchors are linked from the decision-preparation record and
are retained. The former Hub child headings for Self-Description access and
browser preference/workspace had no inbound workspace links and are folded
into the Hub supplement. This is not a claim that no external deep links
exist.

The earlier audit and decision-preparation remain historical evidence of the
decision process; neither is rewritten as though it had already selected the
canonical map. No milestone chronology is moved to Roadmap History in this
checkpoint.
