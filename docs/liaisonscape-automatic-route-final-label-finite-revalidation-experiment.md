# LiaisonScape Automatic-Route Final-Label Finite Revalidation Experiment

Date: 2026-08-31

Status: bounded application experiment; non-normative

## Exact result

`MIXED — FINAL-LABEL REVALIDATION IS INFORMATIVE BUT NOT YET A STABLE SELECTION SEMANTIC`

One finite second route pass can be defined without changing a candidate,
weight, threshold, side rule, or persisted state: use the fresh final Node-label
rectangles made by the current pass as the label input to one new current
arbitration pass. It is materially different from the earlier X2 oracle, which
examined fixed candidate substitutions and selected crossing improvements.

The finite pass is not a safe Production rule. On Lighthouse EN it changes six
ordinary routes; on JA it changes Sofia/Archive substantially. A hypothetical
third pass is stable for EN but changes four JA routes. Thus a locale-independent
one-pass feedback boundary is not established.

## Duplication and source boundary

The prior ordinary-route Node-label experiment is **PARTIAL**, not exact,
overlap. It established that provisional intersections predict final failures
only partially, that candidate-local final-label oracle X2 can reduce English
H2 from seven to two, and that a one-step feed can choose a different route.
It did not execute this all-ordinary-route B1 transformation.

The live pipeline remains:

```text
positions → provisional Node labels → fixed/ordinary routes
          → Relation labels → final Node labels
```

Final labels consume routes; they do not feed the same production route pass.
The diagnostic B1 pass is exactly one additional fresh arbitration using the
Pass-1 final Node-label rectangles. It then regenerates Relation and final Node
labels. It does not iterate. All current 33 candidates, hard penalty, halo,
Node and occupied-path terms, canonical order, and parallel physical-side rules
remain unchanged.

## Target-scoped measurement correction

The incomplete release-frontier work used global PNR/FNR counts where a target
candidate decision required target ownership. This experiment records target
PNR/FNR as `Relation | foreign Node-label owner`; endpoint labels are excluded.
Global counts remain context only. The temporary harness and its output were
removed after use.

## Feedback probe and safety boundaries

A single hypothetical next feed of B1 final labels produces no additional EN
route change (**S1**), but changes four JA routes—`clara-lighthouse`,
`clara-maya`, `clara-thomas-mentors`, and `clara-thomas-supervises`—(**S5**).
This is a diagnostic stability probe only; a third production pass was not
implemented.

No new foreign-Node, occupied-path, reverse-endpoint-parallel, or
obstacle-side-parallel acceptance claim is made. The diagnostic reuses the
current code paths and their side safeguards, but the dedicated parallel
fixtures were not rerun in this checkpoint. Route total is secondary and was
not used to accept or reject B1. No numeric tuning occurred.
