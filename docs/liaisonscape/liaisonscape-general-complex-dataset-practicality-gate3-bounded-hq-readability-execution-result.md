`Occupied-Geometry Feasibility-First Extent Growth`

This was chosen because it is the latest source-supported lineage with all of
the following evidence:

- extent is output rather than a fixed viewport constraint;

- bounded 2/4/8-sweep feedback already exists;

as a new family. Their evidence remains useful, but the single-connected

## Minimal release blocker

The blocker is now narrower than “complete all Initial Layout research.” It is
the absence of one bounded HQ operation that demonstrates both:

- readable, route/Relation-label-associated Actual Product output for an
  ordinary or moderate complex coordinate-less Dataset; and
- a complete credible execution budget including candidate generation,
  Product-authoritative verification, Worker/main-thread behavior, and total
  user-visible wall time.

The 14/49 dense case remains a stress control; complete resolution of every
dense stress geometry is not required by itself. It is still useful evidence
that the selected family cannot be called universally release-ready. The
current Auto Layout button is a separate Product decision concern because its
observed result is worse than Fast; this checkpoint does not remove, hide, or
replace that button.

If a later bounded candidate meets both conditions, Gate 2 may be closed
without adopting a production provider, changing Product default, or
activating Adaptive Cascade. If not, the release decision should retain Fast
as the usable start and keep the HQ fallback/release bar explicitly open,
without returning to an unrestricted solver search.
