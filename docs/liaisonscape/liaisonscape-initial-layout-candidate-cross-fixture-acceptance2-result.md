## Adoption authority audit

The current Product opening path uses `settleInitialPlacement()` from
`src/auto-layout.ts` when a coordinate-less Dataset is accepted. That is a
generic deterministic runtime path over arbitrary Dataset topology. Stored
Coordinates remain authoritative when present.

The Post candidate is currently produced by
`constrainedPostStructuralRelaxation()` in
`tools/generic-crossing-search.mjs` and exposed through
`experimental/product-evaluation-seam/geometry-inspection1/main.tsx`. The
inspection seam replaces coordinates only in an in-memory diagnostic clone;
it does not provide a generic runtime authority, a bounded runtime budget, or
a locale-independent materialization rule for arbitrary Datasets.

Therefore the evidence supports the following bounded conclusion:

```text
research candidate eligibility = SUPPORTED FOR FURTHER ADOPTION DESIGN
global Product initial-placement adoption = HOLD
current Product automatic placement = UNCHANGED
```

Hard-coding the observed public samples, copying their coordinates, or routing
all arbitrary coordinate-less Datasets through the diagnostic search would
confuse fixture evidence with Product authority and would not establish a
safe adoption boundary. No such change was made.

## Required next adoption gates

A separate explicit adoption checkpoint would need to define and validate:

1. a generic runtime algorithm or service boundary for arbitrary
   coordinate-less Datasets;
2. a deterministic budget and fallback for larger or denser Datasets;
3. locale-aware inputs without cross-locale coordinate reuse;
4. Product regression coverage for stored, mixed, and coordinate-less opening;
5. ownership/dirty-state behavior showing that derived placement remains
   derived until intentional user adoption; and
6. controlled routing/label attribution so the open presentation tracks are
   not silently bundled into layout adoption.

Until those gates exist, the correct adoption result is HOLD, despite the
positive user observation across the compared cells.
